## 0. 원칙 3가지

**① 브랜치보다 스캐폴드가 먼저다.**
main에 뼈대를 올린 뒤 분기한다. 순서를 뒤집으면 네 명이 각자 `pyproject.toml`을 만들어 머지마다 충돌한다.

**② 빈 폴더에 `.gitkeep` 대신 `README.md`를 넣는다.**
GitHub에서 폴더를 클릭하면 그 자리에서 바로 보인다. 빈 폴더 자체가 설명서가 된다.

**③ 루트 README에는 전체 트리를 앞세우지 않는다.**
큰 트리는 첫날 한 번 보고 안 본다. 사람별로 "지금 뭘 쳐야 하는지"를 앞에 두고 트리는 접어 둔다.

### 이번에 조정한 것 하나

`agents/policy_agent/core/` → **`agents/policy_agent/nodes/`** 로 이름을 바꾼다.
루트에 이미 `core/`(Auditor 엔진)가 있어서 같은 이름이 두 개가 되면
`from core.schemas import ...` 와 `agents/policy_agent/core/sql_generator.py` 가 대화에서도 코드에서도 섞인다.
LangGraph 노드를 담는 폴더라 `nodes/`가 의미도 더 맞다. **준원에게 이 변경을 알린다.**

## 2. 공유 파일 6종

### 2-1. `pyproject.toml`

```toml
[project]
name = "agent-migration"
version = "0.1.0"
description = "MABC 2026 — Agent Upgrade Auditor & Policy Testbed"
requires-python = ">=3.11"
dependencies = [
    "pydantic>=2.0",
]

[project.optional-dependencies]
auditor = [
    "typer",
    "jinja2",
    "openai",
    "python-dotenv",
]
testbed = [
    # 팀원이 채웁니다 (langgraph, langchain-core 등)
]
dev = [
    "pytest",
    "ruff",
    "pre-commit",
]

[tool.uv]
package = false

[tool.ruff]
line-length = 100
target-version = "py311"
```

**왜 패키지를 하나로 두는가**
Testbed는 LangGraph·DB가, Auditor는 Pydantic·Jinja2가 필요하지만 2주 반짜리 프로젝트에서 패키지를 둘로 쪼개면 얻는 것보다 잃는 게 크다. extras로 나누면 각자 필요한 것만 설치하고, 같은 파일을 건드려도 서로 다른 줄이라 충돌해도 1초면 끝난다.

`package = false`는 이 리포를 설치 가능한 패키지가 아니라 **의존성 관리 대상으로만** 쓰겠다는 뜻이다. 실행은 루트에서 `uv run python -m apps.cli` 형태로 한다.

## 7. 자주 나오는 문제

| 증상 | 원인 | 해결 |
|---|---|---|
| `uv: command not found` | uv 미설치 | `curl -LsSf https://astral.sh/uv/install.sh \| sh` 후 셸 재시작 |
| `Permission denied (publickey)` | SSH 키 미등록 | GitHub Settings → SSH keys 등록, 또는 HTTPS로 클론 |
| 빈 폴더가 push 후 안 보임 | git은 빈 폴더를 추적하지 않음 | `.gitkeep` 또는 README.md 넣기 |
| `.env`가 커밋됨 | gitignore보다 먼저 add됨 | `git rm --cached .env` 후 커밋. **키는 즉시 재발급** |
| main에 push가 막힘 | 보호 설정 (정상) | 브랜치에서 작업 후 PR |
