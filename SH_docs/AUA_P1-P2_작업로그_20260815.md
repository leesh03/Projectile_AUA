## 2. P2 — 결정론 코어

### 2.1 Loader & Validator (`core/schemas/loader.py`)

`AuditBundle`을 **관대하게** 파싱한다 — trial/trace 레코드 1건이 깨져도 전체를 죽이지 않는다.

- `bundle_id`/`suite`/`baseline`/`candidate` 자체가 깨지면 `ContractViolation`으로 즉시 중단
  (복구 불가 영역)
- `trials`/`traces`는 레코드 단위로 개별 검증 → 실패한 것만 `SkippedRecord`로 격리, 나머지는 진행
- `testcase_id` 기준 페어링 → 한쪽 버전에만 있는 testcase는 `unpaired_testcases`로 분리하고
  비교 대상 trial 목록에서 제외
- 페어링된 testcase 중 trial 수가 2 미만인 게 하나라도 있으면 전역 `low_confidence=True`

검증용으로 `scenario_broken.json`을 일부러 깨뜨려서 만듦: `case_19`/`case_20`은 V1 trial이
아예 없고(페어링 실패), `case_05` trial 1의 V1 레코드는 `stop_reason` 키 자체가 빠져 있음
(필수 필드 누락). 로더가 예외 없이 `LoadResult`를 반환하고, 두 문제를 각각 정확히 잡아내는 것을
테스트로 확인함.

### 2.2 Metric Aggregator (`core/diff/aggregate.py`)

testcase → 버전 → 전체 순 집계. `success_rate`, `policy_accuracy`, `tool_error_rate`,
`avg_retry`, `avg_tokens`, `avg_latency_ms`, `stop_reason` 분포, `safety_violations` 카운트.
`difficulty` 필드가 있으면 난이도별 집계도 같이 생성. testcase의 "성공"은 보수적으로
정의함 — 그 버전의 trial 전부가 성공해야 PASS (하나라도 실패하면 재현 안정성이 없다고 봄).

### 2.3 Deterministic Diff (`core/diff/compare.py`)

- rate류 지표(success_rate 등)는 퍼센트 포인트(`delta_pp`), 비용류 지표(토큰/지연)는
  상대 변화율(`delta_pct`), `avg_retry`는 절대 차이(`delta`)로 단위를 지표 성격에 맞게 고정
- Flip 행렬: `preserved` / `regression` / `improvement` / `persistent` 4분류
- 분모 0(변화율 계산 불가) · 빈 목록(표본 없음) 방어 처리

### 2.4 골든 테스트 (`tests/auditor/`)

pytest 19개 작성, 전부 통과. `ruff check .` 클린.

- 스키마 라운드트립·거부 케이스 (`test_schemas.py`)
- `scenario_broken.json`의 페어링 실패/필드 누락 처리 (`test_loader_contract_violations.py`)
- L1~L3 파이프라인 결과를 골든 JSON과 비교 (`test_p2_golden.py`) — 집계 로직을 고의로 바꿀 때만
  `tests/auditor/golden/generate_golden.py`로 재생성

**실행 결과로 확인한 수치** (설계 의도와 정확히 일치):

| 시나리오 | 확인된 값 |
|---|---|
| scenario_a | regression 5건 (`case_03,07,12,15,18`), tool_schema_valid_rate 100%→75% |
| scenario_clean | flip 전부 preserved 20건, 모든 delta = 0 |
| scenario_c | avg_retry 0.25→1.75 (E-01 임계값 0.5 초과 확인), regression 6건 |
| scenario_safety | safety_violations 0→1 |
| scenario_broken | unpaired 2건, skipped_trial 1건, low_confidence=True, testcase_count 18 |

**LLM 호출 0회** — P2까지는 전부 코드 계산이다 (`core/diagnosis/`는 아직 손대지 않음).

## 4. 남은 것 / 참고

- **`main` 브랜치 보호(PR 필수)가 아직 설정 안 돼 있음.** P0-3 체크리스트 항목인데 실제로는
  직접 push가 그냥 됐다. 팀원 합류 전에 GitHub Settings에서 설정 필요.
- `pyproject.toml`에 `[tool.pytest.ini_options] pythonpath = ["."]`을 P2 커밋에 넣었는데
  `Auditor`에만 있고 `main`에는 아직 반영 안 됨. 사소한 dev-tooling 변경이라 급하지 않지만,
  다음 `contract/*` 동기화 때 같이 올리면 됨.
- `SH_docs/`(이 폴더)는 아직 git에 추적되고 있지 않음. 개인 메모 용도로 의도적으로 뺀 것인지
  확인 필요.
